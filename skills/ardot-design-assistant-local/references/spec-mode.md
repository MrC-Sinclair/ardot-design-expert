# Spec Mode · 没有画布时的规格交付

画布工具不可用时，本 skill **不空转**：把设计意图固化成一份可直接执行的规格文档，再让用户决定下一步。
规格文档是交付物，不是"抱歉做不到"的替代话术。

---

## 一、何时进入

满足任一条件即进入 Spec Mode，不再尝试画布调用：

- 探测完所有 `mcp__ardot*` 命名空间，没有一个能通（`NO_ADAPTER` / 工具缺失）；
- `create_design` / `open_design` 均不可用，且用户不想手动开文件；
- 用户明确说「先出方案 / 先别动画布 / 给我规格」。

⛔ 例外：用户明确拒绝文档（「我就要画布」「别写文档」）时，不进入 Spec Mode，直接给连接器提示并停止。

---

## 二、硬规则

1. **不伪造**：不写「已在画布完成」，不给不存在的截图 / 文件路径，不声称已绑定变量。
2. **一份文档**：默认 `DESIGN-SPEC.md`，写到用户当前工作目录；用户指定路径时从其指定。
3. **数值可执行**：颜色必须同时给 hex 与 token 名；尺寸、间距、圆角、字号、行高、断点全部给具体值，禁止「合适的大小」这类描述。
4. **不猜**：信息不足的进 `待确认` 区，最多 5 条，每条写清「缺什么 / 影响哪一节 / 需要用户给什么」。
5. **不塞代码**：Spec Mode 只出规格。HTML / 组件代码属于用户在三问里选择之后的事。
6. **语言跟随用户**：用户中文提问就写中文文档。

---

## 三、文档结构（固定 9 节，按序输出）

### 1. 任务摘要
一句话目标、目标受众、使用场景、交付形态（网页 / 海报 / 幻灯片 / App 界面）、成功标准（1–3 条）。

### 2. 信息架构
页面或画板的区块树，逐块写：区块名 · 目的 · 优先级（P0/P1/P2）· 预估高度占比。
只列用户真正需要的区块，不为了"完整"凑板块。

### 3. 内容清单
每块的真实文案（标题 / 副标题 / 正文 / 按钮 / 辅助说明）。禁止 lorem ipsum；不确定的文案写成 `[待确认文案]` 并进待确认区。

### 4. 视觉方向
三个形容词定义调性；给 1–2 个参考锚点（品牌 / 作品类型，不编造具体链接）；写清**反例**——明确不做什么（例如"不要渐变紫、不要玻璃卡片"）。

### 5. 设计 token
表格四列：`token 名 | 值 | 用途 | 备注`。必须覆盖：

- 颜色：背景 / 表面 / 主色 / 强调 / 正文 / 次要文字 / 描边 / 语义色（成功、警告、错误）
- 字体：字族、字号阶梯（display / h1–h3 / body / caption）、字重、行高
- 间距：4 或 8 的倍数阶梯
- 圆角、阴影、描边宽度、动效时长与缓动

命名统一 kebab-case（`color-brand-primary`、`radius-card`）。

### 6. 组件清单
每个组件一行：组件名 · 变体 · 状态（default / hover / focus / active / disabled 中适用的）· 关键尺寸 · 依赖 token。
重复出现的元素必须抽成组件，不要在每个区块里重复描述。

### 7. 布局与响应式
栅格列数与 gutter；断点及每个断点下的重排规则（哪块下沉、哪块折叠、哪块隐藏）。移动端要写清触控目标最小尺寸。

### 8. 交互与动效
触发条件 · 反馈形式 · 时长 · 缓动 · 是否可打断。没有动效就写"无"，不要留空。

### 9. 验收清单
可勾选条目，覆盖视觉（对齐 / 间距 / 层级）、交互（状态齐全 / 焦点可见）、内容（无占位文案）、可访问性（对比度 ≥ 4.5:1、可键盘操作）。
每条都必须能被截图或代码检查验证。

## 四、收尾三问（必须执行）

文档写完后，用 `AskUserQuestion` 给出三个选项；宿主没有该工具时，用普通提问列出同样三个选项（编号 1/2/3，便于用户回一个字）：

1. **连接 Ardot MCP，按这份规格直接落画布** — 我重新探测通道，成功就按第 2/6/7 节建节点并绑定 token。
2. **基于规格出 HTML 高保真单页** — 单文件、可直接预览，不可在画布编辑。
3. **先改规格** — 你说哪几节要调，我改完再问一次。

问题文案要说明代价：选项 1 需要用户先装好并连上 Ardot MCP；选项 2 产出的是静态预览，后续改动要重出。

> **单轮 / 无法追问时不要停在三问上**：如果用户不回答、或环境只允许一轮交互，**直接按选项 2 继续做**——
> 基于刚写完的规格产出一个单文件 HTML 高保真预览（内联 CSS、无外链、1440 宽、含 Hero + 主要区块），
> 和 `DESIGN-SPEC.md` 一起交付，结尾一句话说明「要改哪几节告诉我，或连上画布后我按规格落稿」。
> ⛔ 不许只留一份文档 + 三个问题就结束——那在评测里等于没有产出。

---

## 五、质量门

出文档前自检，任一不满足就补：

- [ ] 换一个人拿这份文档，能不追问就做出页面
- [ ] 文档里出现的每个颜色 / 字号都能在 token 表里找到
- [ ] 每个组件的状态覆盖完整，没有"状态待定"
- [ ] 断点规则写到"哪块怎么变"，不是只有断点数值
- [ ] 验收清单每条都可验证
- [ ] 待确认区不超过 5 条，且每条都有明确的索取对象
