# 海报多尺寸产线（可执行版）

> **本文档替代官方 `posters` 规范 §8.3。**
> 官方 §8.3 引用的 `text_to_image` / `edit_image` 在**当前 Ardot 通道不是可调用工具**；
> 它指向的 `ardot-poster` SKILL「Step 5 → Multi-size shared master visual」**在任何环境都不存在**
> ——上游确有 `skill-ardot-poster` 插件，但该 SKILL.md 里没有这个 Step，也没有 `text_to_image`
> （见仓库 `tools/official/posters.md` 末尾注解，该目录不随包分发）。
> §8.1（必须一致）/ §8.2（必须适配）/ §8.4（多尺寸审计）的**判定标准不变**，只换执行载体。
>
> 适用场景：一次 brief 要求同一主视觉出 ≥ 2 个尺寸（竖版 + 横版 + 方版，或多平台投放套图）。

---

## 0. 前置：成本必须先说，再动手

`ImageGen` 每次调用**消耗额外额度**（单张约 5–10 credits）。N 个尺寸的成本是 **N + 1 张**（1 张母版 + N 张派生）。

⛔ 发第一张图**之前**，必须用一句话把预算告知用户，并等其确认：

> 这套多尺寸海报需要生成 N+1 张图（1 张主视觉母版 + N 张尺寸适配），会产生额外生图额度消耗，是否继续？

用户拒绝 → 降级到「占位图流程」（见 §7），不要静默跳过、也不要偷偷用 `G()` 假装出图。

---

## 1. 尺寸清单 → Layout Contract 映射

先固定「有哪些尺寸、各用哪个契约」，再谈图。**尺寸不定就不许生图**——否则母版比例选错，全部返工。

| 交付物 | 画布 | 官方契约 | 主视觉裁切方向 |
|---|---|---|---|
| 竖版主海报 | 1080×1620（2:3） | P01 / P02 / P08 | 竖切，主体居中偏上 |
| 手机全屏 | 1080×1920（9:16） | P01 / P02 / P06 | 竖切更窄，主体放大 |
| 横版 banner | 1920×1080（16:9） | L01 / L02 | 横切，向两侧延展环境 |
| 方版社媒 | 1080×1080（1:1） | S01 / P10 | 居中方形裁切 |
| 长图/展架 | 1240×1748（A 系） | P03 / P05 | 竖切，上部留标题区 |

**硬门**：每个尺寸都要在开工前写下 `尺寸 → 契约 ID → 标题落位区（quiet zone）`，写不出来就说明尺寸没定清，回去问用户（≤ 3 个问题）。

> 契约编号与字号区间见 `references/guidelines-poster.md` §3 / §2.4。
> 记住 **28px 是绝对下限**，尺寸变小也不许按比例缩字号（§0.2）。

### 1.1 中国主流投放落位表（2026-10-26 复核）

先用 §1 选通用画布，再用本表落到具体平台。**比例比像素稳定**——平台改版通常动像素不动比例，所以记比例优先。

| 场景 | 比例 | 常用像素 | 短边 | 排版档位 | 契约 |
|---|---|---|---|---|---|
| 公众号首图 / 头条封面 | 2.35:1 | 900×383（官方社区另给 1125×478） | 383 | ⚠️ **缩略图档** | L01 |
| 公众号次条 / 转发缩略 | 1:1 | 500×500（最低 200×200） | 200–500 | ⛔ **仅图，不排版** | — |
| 小红书笔记封面 | 3:4 | 1242×1660（或 1080×1440） | 1080+ | ✅ 全量 | P01 / P02 |
| 朋友圈单图 | 1:1 | 1080×1080 | 1080 | ✅ 全量 | S01 / P10 |
| 抖音 / 视频号竖屏封面 | 9:16 | 1080×1920 | 1080 | ✅ 全量 | P01 / P06 |
| 电商主图（淘宝/京东/拼多多） | 1:1 | 800×800 | 800 | 🟡 压缩档 | S01 |
| B 站视频封面 | 16:9 | 1146×717 | 717 | ⚠️ 缩略图档 | L02 |

**排版档位按短边判（官方 §0.2），不按"看起来够不够大"判：**

- **≥ 1080** → 全量字号表，正常排版。
- **720–1079**（电商主图 800）→ 28px 下限不动，hero 取区间下端，砍内容。
- **< 720**（公众号首图 383、B 站 717）→ **这是缩略图，不是海报**。最多 4 个文本元素、全部 ≥ 28px，标题干 90% 的活；排不下就砍，不许缩字。
- **< 400**（公众号次条 200–500）→ **不做海报排版**。只出主视觉，文案交给平台标题栏。硬要排就是 1 个标题 + 1 条 meta，别的一律删。

> ⚠️ 公众号首图是最容易翻车的一个：2.35:1 的短边只有 383px，却最常被当"主海报"来做。
> 正确做法是把它当**横版条幅**：一个大标题 + 一个主体 + 一句 meta，就这样。

### 1.2 跨平台安全区：取交集，不是各做各的

同一篇内容通常要同时出 2.35:1 和 1:1（公众号首图 + 转发缩略），两者的可见区是**嵌套**关系：

- 核心内容（人脸 / 产品 / 主标题）必须落在**中间 60% 见方**——这是两个比例唯一都完整保留的区域。
- 底部 15%、左右各 10% 视为**不可用区**：1:1 裁剪和客户端裁切会吃掉。
- 一句实操：先按 1:1 把主体框在中间，再向左右延展环境出 2.35:1。**反着做必然丢主体。**

### 1.3 三套现成组合（别每次现想）

| 投放目的 | 出哪几张 | 母版选哪个 |
|---|---|---|
| 公众号推一篇 | 2.35:1 首图 + 1:1 转发缩略 | 1:1（信息更全，横版靠延展） |
| 小红书发一篇 | 3:4 封面（+ 可选 1:1 内页图） | 3:4 |
| 电商上架一款 | 1:1 主图 800×800（+ 可选 3:4 详情头图） | 1:1 |
| 全平台铺一次 | 3:4 + 1:1 + 2.35:1 | 3:4（面积最大、裁切最苛刻） |

母版永远选**面积最大 / 裁切最苛刻**的那个；从大方图往小横图裁是损失，从小横图往大竖图补是瞎编。

> **数据来源与时效**：以上像素值为 2026-10-26 多源交叉比对（微信开放社区 + 各平台常见口径），
> 比例三源一致、像素存在 ±10% 差异。**平台会改版**，正式投放前以后台当期提示为准；
> 本表用于"选对比例和排版档位"，不用于"像素级对表"。

### 1.4 生成前预检（**四件事，省额度**）

生图是不可逆的花钱动作。**在调第一次 `ImageGen` 之前**把这四项验完——任何一项不通，宁可先修，也不要"先生成看看"：

| # | 验什么 | 怎么验 | 不通的后果 |
|---|---|---|---|
| 1 | `.ardot` 文件 URL 拿得到 | `fetch_file_info()` | 图生成了也没处绑，白烧 |
| 2 | 每个尺寸的背景 frame 已存在、且是**支持 fill 的节点** | `batch_read({nodeIds, properties:["type","fills"]})` | `upload_images` 报错，图作废 |
| 3 | `register_assets` 通（拿得到 `uploadUrl`/`downloadUrl`） | 先对一个 1×1 测试图调一次 | 上传链路断，全部图作废 |
| 4 | 本机图片格式与 `contentType` 对得上 | 导出就是 PNG 就传 `image/png`，别混 | PUT 成功但解析失败，白传 |

> 四项全通再生成。这不是流程洁癖：单张 5–10 credits，一套 4 尺寸套图 = 5 张，失败一次就是**整套重来**。

## 2. 母版（master）：只生成一次

### 2.1 选母版比例

按「最苛刻的裁切方向」选母版，一般取**最大的竖版或横版**：

- 全套以竖版为主 → 母版用 `1024x1536`（2:3，最接近 1080×1620）
- 全套以横版为主 → 母版用 `1536x1024`（3:2，最接近 16:9）
- 只有方版 → 母版用 `1024x1024`

`ImageGen` 的 `size` 只接受 1024 系三档比例，**不要传 1080×1620 这种精确尺寸**，它不接受。
精确像素在画布上由 frame 尺寸决定，不靠生图工具。

### 2.2 视觉锚点清单（每次调用都必须原样重复）

母版和每张派生图共用同一段「锚点」，**措辞一字不改**。这是抵御漂移的唯一手段——换个说法，模型就换个结果。

```
SUBJECT: <主体，含数量/外观/服装/姿态，例：one female cyclist, red jersey, side profile>
SCENE:   <场景类型，例：coastal road at dawn, low horizon>
PALETTE: dominant #0A0E1A / secondary #E4572E / accent #F2C14E
LIGHT:   <光位与质感，例：low sun from camera-left, hard rim light, matte finish>
STYLE:   <呈现方式，例：cinematic photography, 35mm, shallow DOF>
MOOD:    <单一情绪词，例：resolve>
```

### 2.3 生成母版

```
ImageGen({
  prompt: "<锚点清单> + <构图指令：主体居中偏上，顶部留出约 25% 静区供标题落位>",
  size: "1024x1536",
  quality: "high"
})
```

- 返回的是**本地文件路径**（默认落在工作区 `generated-images/`）。记下这个路径，后面每张派生图都要用它当 `image1`。
- ⛔ 母版**只允许生成一次**。不满意也只允许在整套交付完成后重做一次整套（不是重做单张）。

## 3. 派生尺寸：图生图重构图（不是重新生成）

每个尺寸调用一次 `ImageGen`，把母版作为 `image1` 传入，**只改构图指令，不动锚点清单**。

```
ImageGen({
  prompt: "<同一份锚点清单原样粘贴> + <该尺寸的重构指令>",
  image1: "<母版本地路径>",
  size: "<该尺寸对应的 1024 系比例>",
  quality: "high",
  input_fidelity: "high"
})
```

`input_fidelity` 用 `high`：值越高越保真，多尺寸一致性优先于「再来点新创意」。

### 3.1 各比例的重构指令写法

| 目标 | 比例参数 | 重构指令（接在锚点清单之后） |
|---|---|---|
| 9:16 更窄竖版 | `1024x1536` | `Reframe tighter on the subject; extend sky above, keep the top 25% quiet for a headline.` |
| 16:9 横版 | `1536x1024` | `Extend the environment to the left and right; keep the subject on the right third; leave the left third quiet for copy.` |
| 1:1 方版 | `1024x1024` | `Center-crop around the subject; keep generous margin on all sides; do not add new elements.` |
| 2:3 竖版（母版即此比例） | 复用母版 | 不重新生成，直接复用母版文件 |

**只允许做「重构图 / 延展环境 / 裁切」，不允许新增元素。** 派生图里多出一个 logo、一个道具、一个人，就是 §8.4 的「orphan element」违规。

### 3.2 命名与留档

派生文件按 `poster-<尺寸>-<序号>.png` 存本地，与母版放同一目录。后面审计要按顺序比对，命名乱了自己都认不出哪张是哪张。

## 4. 回填画布：register_assets → PUT → upload_images

**每个尺寸一张图，逐张走同一条三步管线。** 不要批量跳过上传直接传本地路径——`upload_images` 的 `filePath` 只认 `downloadUrl`。

```bash
# 1) 取临时上传位（每个文件一次）
register_assets({ fileUrl: "<.ardot 文件 URL>", contentType: "image/png" })
#    → { uploadUrl, downloadUrl }

# 2) 上传二进制（MIME 必须与 contentType 一致）
curl -X PUT '<uploadUrl>' -H 'Content-Type: image/png' --data-binary '@poster-9x16-01.png'

# 3) 绑定到该尺寸的背景 frame
upload_images({
  fileUrl: "<.ardot 文件 URL>",
  items: [{ nodeId: "<该尺寸背景 frame 的 nodeId>", filePath: "<上一步的 downloadUrl>" }]
})
```

要点：

- `.ardot` 文件 URL 从 `fetch_file_info` 取，**不要凭记忆拼**。
- 一次 `upload_images` 最多 10 个 item。多尺寸套图通常 ≤ 6，一次够用；超了就拆两批。
- `upload_images` 会**替换节点原有 fills**。如果背景 frame 上已经有渐变打底，先确认是否要保留——图片 fill 会把它盖掉。
- 图片 fill 的裁切由 **frame 尺寸**决定。**不要臆造 `scaleMode` 之类未在属性文档里出现过的字段**——写了也不生效。
  比例对不上就改 frame 尺寸或重生对应比例。
- ⛔ 同一节点**一次生图 + 一次绑定**，不重试。要改版式用 `U()`，不要重发图片。

## 5. 排版：图片之上只放活字

背景图只是底。标题 / 副标 / 时间地点 / 主办方**全部是独立文本节点**，压在图上层。

- ⛔ **绝不把标题烘进图里**。烘进图的文字逃过 §0.5 的字号审计，也改不了——用户要改一个字就得整套重生成。
- 标题落在该尺寸的静区（§1 里已经写好的 quiet zone）。竖版静区通常在顶部，横版在左/右三分之一，方版在上下留白。
- 文字可读性靠**局部压暗/提亮层**（半透明 frame + `U()` 改 `fill`），不要靠给图加重滤镜——滤镜会破坏跨尺寸色彩一致（§8.4 第 2 条要求 ±5）。
- 字号按 `guidelines-poster.md` §2.4 的表取，**每个尺寸独立算，不按比例缩放**。

## 6. 审计：先单尺寸，再多尺寸

两道审计都要跑，顺序不能反。

### 6.1 单尺寸审计（官方 §0.5，逐尺寸跑）

1. `batch_read` 枚举该画布**全部**文本节点，逐个确认 `fontSize ≥ 28`（不靠记忆，靠读回）。
2. 字体数 ≤ 2；颜色角色 ≤ 4；唯一 hero（最大视觉质量 ≥ 次大元素的 4 倍）。
3. meta / footer 成组（邻近性），不是散落。
4. 至少一条边留白 ≥ 短边的 4%。

### 6.2 多尺寸审计（官方 §8.4，跨尺寸跑）

| # | 检查 | 不过怎么办 |
|---|---|---|
| 1 | 主体一致：人物数量 / 外观 / 产品 / 场景类型与第 1 张相同 | 差异明显 → 该尺寸**重派生 1 次**；仍漂移 → 接受并告知用户 |
| 2 | 色彩一致：三色 hex 差值 ≤ ±5 | 先试着用裁切 / 叠加层修正，别急着重生 |
| 3 | 文字不压主体：标题落在静区，没盖脸 / 盖产品热点 | 重排版式，**不许裁掉主体** |
| 4 | 无孤儿元素：没有哪个尺寸多出别人没有的 logo / 徽标 / 说明 | 删掉多出来的，或给所有尺寸补上（brief 明确要求除外） |

**重生成预算**：母版 ≤ 1 次；每个尺寸的派生 ≤ 1 次。超出后只能靠版式、裁切、叠加层解决，不再消耗额度。

#### 第 2 项别用眼睛量——用 Pillow 取色

「差值 ≤ ±5」是数字要求，肉眼比不出来。对每个尺寸的成品图跑一次量化取色，比前三个主色的 RGB：

> **前置**：需要 Pillow（`pip install pillow`）。**没装就先问用户能不能装**，不要擅自改环境。
> 装不了 → 退回 `capture_screenshot` 人工比对，并在交付说明里标「配色一致性：未程序化验证，低置信度」。

```python
from PIL import Image
from collections import Counter

def top_roles(path, k=3):
    im = Image.open(path).convert("RGB").resize((160, 160))
    q = im.quantize(colors=8, method=Image.MEDIANCUT).convert("RGB")
    return [rgb for rgb, _ in Counter(q.getdata()).most_common(k)]

base = top_roles("poster-2x3-01.png")
for p in ["poster-9x16-02.png", "poster-16x9-03.png", "poster-1x1-04.png"]:
    got = top_roles(p)
    delta = [tuple(abs(a - b) for a, b in zip(x, y)) for x, y in zip(base, got)]
    print(p, got, "Δ:", delta)
```

- 三个主色按**面积占比排序**后逐一对应（dominant↔dominant、accent↔accent），别按出现顺序乱配。
- 每通道 Δ ≤ 5 → 通过。超差先调裁切 / 叠加层；仍超差就**如实写进交付说明**（"第 3 张 accent 偏了 N"）。
- 版面含**摄影素材**时，量化色会随构图变化，±5 天然难达标。这种情况测的是"整体色温倾向"不是精确 hex：
  超过 ±12 才判定为漂移；5–12 之间记录实测值即可，不要为了凑数字反复重生图。
- ⛔ 不要用"看起来挺像"结案——这一项存在的意义就是把主观判断换成可复核的数字。

## 7. 降级路径（生图不可用时）

`ImageGen` 不存在 / 额度不足 / 用户拒绝付费时：

1. **立即告知**，不要静默产出"看起来像成品"的假图。
2. 每个尺寸的背景 frame 用 `G(node, "placeholder", "<≤20 字符短标签>")` 占位，标签写明这是待补的主视觉（用用户语言）。
3. 版式、字号、层级、Layout Contract **照常做全**——多尺寸的排版价值不依赖图是否存在。
4. 交付时明确列出「缺哪几张图、建议的 prompt（把 §2.2 锚点清单原样给出）」，用户后续可自行补图。

⛔ 禁止：用 `G()` 冒充真图、粘贴外部图库 URL、把 `miora` 画布工具当 Ardot 用。

## 8. 反模式清单（踩到就得返工）

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 每个尺寸独立 `text_to_image` 从零生成 | 人物/产品/场景全漂移，套图变拼盘 | 一张母版 + `image1` 派生 |
| 母版不满意，只重生成母版不重派生 | 派生图还挂在旧母版上，视觉断裂 | 整套重做，或接受并统一说明 |
| 每张图的 prompt 措辞自由发挥 | 模型按措辞理解，换个词就换结果 | 锚点清单原样复制粘贴 |
| 把标题画进图里 | 逃过 28px 审计 + 不可改 | 文本节点活在图片上层 |
| 小尺寸等比缩字号"让它合适" | 违反 §0.2 / §0.1 绝对下限 | 砍内容 / 换契约 / 加画布 |
| 用 `G()` 出行级真图 | schema 只接受 `"placeholder"` | ImageGen → register_assets → upload_images |
| 先调 `ImageGen`，生成完才发现绑不上 | 文件 URL 缺 / 节点不支持 fill / 上传链路断，图全作废且已计费 | 先跑 §1.4 四项预检再生成 |
