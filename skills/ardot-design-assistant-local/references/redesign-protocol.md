# 改版协议（Redesign Protocol）

> **触发**：用户说「改一下这版」「现代化一点」「翻新」「重做」「优化这个页面」「换成 XX 风」，
> 且**已有存量设计稿**（`.ardot` 文件或已上线页面）。
> 从零新建 → 不用本文，直接回 `SKILL.md` 主流程。
>
> **本文解决的是"改"这件事本身**：改多少、先改什么、什么不许碰、怎么证明没改坏。
> 现有 `design-review-workflow.md` 只负责**挑毛病**，`code-review-workflow.md` 只负责**对齐代码**，
> 两者都不回答"接下来怎么下手"。

---

## 0. 先判模式（硬门，判错整件事白做）

| 模式 | 典型信号 | 做法 |
|---|---|---|
| **绿地新做** | 没有存量稿；"重新设计一版" | 不走本文 |
| **保留式现代化** | "别动结构"、"只换皮"、"同样的风格升级一下"、"品牌不能变" | 保 IA + 品牌，只动视觉层（§3 的 1–5 级） |
| **推翻式重构** | "完全换个样子"、"不像现在这样"、"重做" | 保**内容**，换视觉语言与布局（可走到 6–7 级） |
| **判不出来** | 只有一句"改好看点" | **问一句，不要猜**：*"保留现在的结构和品牌，还是视觉从零重来？"* |

⛔ 不许默认走"推翻式"。用户说"优化一下"时，八成想保留结构——猜错等于把他熟悉的产品改没了。

---

## 1. 动手前审计（缺一项就别改）

| 审什么 | 怎么审（画布） | 用来干什么 |
|---|---|---|
| **品牌令牌** | `fetch_variables`（必做，见 Bind Before Build） | 确定哪些颜色 / 圆角 / 间距**不许动** |
| **结构与层级** | `fetch_editor_state` + `batch_read(readDepth: 3)` | 认清信息架构，避免"顺手删了个区块" |
| **现状旋钮读数** | 看间距规律、圆角一致性、内容密度、居中比例 → 估 `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY` | 改版要**匹配原值 +1**，不是从基线 8/6/4 重开 |
| **视觉基线** | `capture_screenshot`（整页 + 关键区块） | 唯一能证明"没改坏"的证据；也是 before/after 的 before |
| **内容清单** | 把所有可见 `characters` 列出来 | 推翻式可改措辞，但**信息点一个不能丢** |
| **现状问题清单** | 跑 `design-review-workflow` | 改版要有靶子，否则改的只是"感觉" |

**审计产出必须是一张表**（品牌色 / 字体 / 圆角体系 / 区块清单 / 现有问题），先给用户看一遍再动手。
⛔ 跳过审计直接改 = 后面所有"这颜色怎么变了""这块怎么没了"都由你负责。

> 若设计稿对应已上线页面，顺手记下 URL 与页面标题。SEO 基线在设计→代码阶段才有意义，
> 改版画布阶段只要别把页面名改掉就行。

---

## 2. 保留红线（默认不动，除非用户点名）

- **品牌资产**：logo（组件实例不重画）、主色、字体家族
- **结构与导航**：主导航标签文案与顺序、区块的数量与顺序
- **表单**：字段名、字段顺序、必填标记
- **法律与合规**：隐私、条款、备案号、版权行、风险提示
- **签名交互**：用户认得出的那个动效 / 图形语言（哪怕你觉得土）
- **页面命名**：`name` 与页面 ID 映射关系

要动其中任何一条 → **先问**，并在交付说明写「已改 X，因为 Y」。
⛔ 保留式改版里动 IA，是最容易被骂的一种"优化"。

### 品牌色 vs 反套路禁令（顺序别搞反）

`style-guide.md` §9 禁 AI 紫、禁过度饱和、禁霓虹——**禁的是"没有品牌约束时的默认选择"，不是品牌本身**：

- 品牌主色是紫 → **留住紫**，改的是"别自动上紫"这个习惯。
- 品牌色饱和度偏高 → 可以用在品牌元素上；但**正文、大面积背景、次要按钮**仍按可读性要求处理。
- 判断口径只有一句：**这是你选的，还是用户给的？** 你选的受禁令约束，用户给的不受。

⛔ 不许以"反 AI 套路"为理由改掉品牌资产。那不是在纠品味，是在改别人的品牌。

## 3. 现代化杠杆顺序（从便宜到贵，不许跳级）

| 序 | 杠杆 | 具体动作 | 风险 | 什么时候停 |
|---|---|---|---|---|
| 1 | **字体** | **品牌字体锁定不动时**：只调字重 / 字号层级 / 字距 / 行高。品牌字体未锁定（或推翻式）：才换家族 | 低 | 只做这一步就救活了 → 停 |
| 2 | **间距节奏** | 统一 8pt 栅格，加大区块间距与留白 | 低 | 页面"松"下来了 → 停 |
| 3 | **颜色再校准** | 只动**非品牌色**：中性色、表面色、描边、辅助色、状态色。降饱和 / 统一强调色 / 修对比度都在这层做 | 中 | 情绪对了 → 停 |
| 4 | **形状与表面** | 圆角体系、描边、阴影分层（一次只锁一个体系） | 中 | 全局统一了 → 停 |
| 5 | **图片与图形** | 换真实图、统一图标语言（单项目单图标族）。**图标语言属于视觉层可改**；但用户认得出的标志性图形元素（品牌辅助图形、IP 形象）要问 | 中高 | |
| 6 | **Hero 重组** | 改首屏结构与信息顺序 | 高 | 用户确认后再往下 |
| 7 | **整块替换** | 换掉某个 section 的布局家族 | 最高 | **最后手段** |

**铁律：一次只上一级。** 每级做完 `capture_screenshot` 给用户看一眼，确认再继续。

为什么不能跳级：一次改五处，用户说"感觉不对"时你**无法定位是哪一步改坏的**；而且大概率会把
"其实只要换字体就够"的项目，做成"整页重画"。

## 4. 分阶段交付（防整页返工）

1. 选**一个区块**做样板（通常 Hero，或最能代表新语言的那组卡片）。
2. 只改这一块 → 截图 → 用户确认。
3. 确认后才铺到全页。

- 样板没确认就铺全页 = 全页返工。
- **推翻式重构**在样板阶段额外确认一件事：新视觉语言**装不装得下原有信息量**。
  别等做完了才发现"新风格放不下这么多字"，那时候只能二选一砍内容或推翻重来。

---

## 5. 验收：对着审计基线逐项 diff

改完不是"看着挺好"，是**逐项对账**：

| 项 | 判定标准 |
|---|---|
| 品牌色 | 未经授权的颜色变化 = **0** |
| 结构 | 区块数量 / 顺序与审计表一致（声明的调整除外） |
| 内容 | 信息点一个不少（措辞可变） |
| 对比度 | 改过的文字**重新算** WCAG，正文 ≥ 4.5:1（"新配色更好看"不是降对比度的理由） |
| 旋钮 | 与审计读数比，变化幅度符合声明（保留式 ≈ +1；推翻式可大幅变） |
| 字号下限 | 页面本身没有字号下限，只要层级分明；**但改的是海报或 logo 时**，28px（海报）/ 24px（logo 最小高度）照旧生效 |

最后交 **before / after 两张截图 + 一张对账表**。只有 after 不算验收。

---

## 6. 反模式（踩到就得返工）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 没审计就动手 | 改完发现品牌色被换、区块被删 | §1 审计出表，先给用户看 |
| 保留式却重排了 IA | 用户认不出这是自己的产品 | 动 IA 前必须问 |
| 一次改五处 | "感觉不对"但定位不到 | 一次一级 + 每级截图 |
| 只换颜色就叫"现代化" | 一周后还是旧的 | 按 §3 顺序，字体和间距优先 |
| 推翻式不保内容 | 信息点丢失，等于重写 brief | 审计时先列内容清单 |
| 改完只给 after | 无法证明改好了 | before/after + 对账表 |
| 用"更现代"当理由改一切 | 用户的原品牌资产被抹掉 | 每次改动都说得出具体收益 |
